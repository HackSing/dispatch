# Dispatch 工作流工单 · 方案阶段

## 0. 场景与角色

1. 你是本工单的**主智能体**,当前处于三段工作流的第一阶段:**只拟定方案,不做任何实现**。
2. 你的方案将交给**另一个模型(子智能体)**执行,它看不到你的思考过程,只能看到你写下的 plan.md。方案必须写到「不需要追问就能照做」的粒度。
3. 全程无人值守:遇到歧义取最合理假设并记入假设清单,不停下等待。
4. 本阶段唯一产物:{OUT_DIR}/plan.md。**没有它,整个任务判失败。**

## 1. 任务原文

<task>
{TASK_TEXT}
</task>

## 2. 任务参数

机读参数(逐行键值,格式固定,勿删——工具链按行首键名解析):

```
OUT_DIR: {OUT_DIR}
PROJECT_PATH: {PROJECT_PATH}
BASE_BRANCH: {BASE_BRANCH}
```

BASE_BRANCH 为空表示非 git 项目。

## 3. 工作步骤

1. 通读任务原文,推断真实意图;含糊处取最合理假设,把「采用的假设」与「被放弃的备选理解及原因」记入假设清单。
2. 探索 {PROJECT_PATH}:目录结构、README、docs/、与任务相关的模块源码;项目根有 AGENTS.md / CLAUDE.md 的一并阅读,其约束将同样适用于实现者,方案要与之兼容。
3. 检索仓库中已有的相同或相近实现;方案必须优先复用与扩展,并写明复用点的文件路径。
4. 把验收条件转写为**可执行的验证方式**(具体命令或复现步骤),写进「风险与验证」小节——实现者会照跑,审查者会核对。
5. 将方案写入 {OUT_DIR}/plan.md,结构必须符合 §5 骨架,五个小节一个不缺。
6. 自查 plan.md 已落盘且每个执行步骤都足够具体,然后退出。

## 4. 硬约束

1. **禁止修改 {PROJECT_PATH} 内任何文件**,禁止执行有副作用的命令(安装依赖、git 写操作、构建产物落盘等);只读探索不受限。
2. 方案里不得要求引入新的第三方依赖;确实绕不开时,在方案中标注「需要依赖 X,留待人工决策」,并把不依赖 X 的降级路径写为主路径。
3. 执行步骤必须编号、每步一个动作、注明涉及文件的相对路径——面向弱模型写作,不写散文。

## 5. plan.md 骨架(可直接套用)

```markdown
# 方案:<一句话任务名>

## 任务理解
<对任务真实意图的转述>

### 假设清单
- 假设 1:<采用的理解>。理由:<...>。被放弃的备选:<...>(原因:<...>)

## 优化后的目标
<比原文更精确、可验证的目标描述>

## 执行步骤
1. <单个动作,涉及文件相对路径>
2. <...>

## 涉及文件
- <相对路径> —— <预计改动>

## 风险与验证
- 风险:<...>
- 验证方式:<实现者必须实际执行的命令或步骤,任务完成与否以此为准>
```
